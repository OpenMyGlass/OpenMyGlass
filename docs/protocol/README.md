# Companion protocol specification

Reverse-engineered from MyGlass 3.5.8 (phone) and the XE24 system image (Glass). See [`../sources.md`](../sources.md) for provenance.

| Document | Content |
|---|---|
| [`transport.md`](transport.md) | Bluetooth channels, UUIDs/SDP, framing, pairing, keep-alive, reconnection |
| [`handshake.md`](handshake.md) | Version negotiation, handshake sequence, authentication, Google account requirements on XE24 |
| [`messages.md`](messages.md) | `Envelope` field catalog, what Glass does with each field, per-feature sequences, error handling |
| [`proto/glass-xe24/`](proto/glass-xe24) | Schemas reconstructed from the Glass side (`Proto.proto` = companion envelope, `TimelineNano.proto` = timeline items, …) |
| [`proto/myglass-3.5.8/`](proto/myglass-3.5.8) | Schemas reconstructed from the phone side, for comparison |

The `.proto` files are generated by [`tools/re/nano2proto.py`](../../tools/re/nano2proto.py) from the decompiled nano classes and checked with `protoc`. Fields marked `[unverified]` are heuristics (e.g. which enum an `int32` field uses).

Regenerate (requires the local `_re/` workspace):

```bash
python3 -I tools/re/nano2proto.py --out docs/protocol/proto/glass-xe24 \
  _re/jadx/GlassBluetooth/sources/com/google/glass/companion/Proto.java \
  _re/jadx/GlassBluetooth/sources/com/google/googlex/glass/common/proto/*Nano.java
```
